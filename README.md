## Overview

[Mozc UT dictionaries](https://github.com/utuhiro78?tab=repositories&q=mozcdic-ut&type=&language=&sort=) are additional dictionaries for [Mozc](https://github.com/google/mozc).

[Merge-ut-dictionaries](https://github.com/utuhiro78/merge-ut-dictionaries) merges the UT dictionaries into one and modify it for the latest Mozc.

### Additional notes (by @Artanejp , Sep 05, 2026 JST)

**英語で書くのが面倒くさいので、とりあえず日本語で書いておきます。**

元のMozc UT辞書では、不適切な単語をフィルタリングすることが可能になっています。
この仕組みを設けること自体には私も何ら異議はないのですが、個人で辞書を作成する場合や各ディストリビューションで配布を行う際に辞書をMergeする場合に、一律的な基準で単語のフィルタリングを行うというのは問題が起こるかも知れないな。と言う懸念を感じてもいます。

特に、ディストリビューション…DebianだったりUbuntuだったりFedoraだったりFreeBSDだったりと…での配布を考えると、それぞれの行動規範や政治的基準と言うものがバラバラであり、それ自体はFOSSの最大の強みだとは思うのですが、Upstreamである辞書作成側での禁止ワードがUpstreamの設定のままで機械的に反映されてしまうことが却って、それらのポリシーと衝突しかねないという問題を含むことになります。
勿論、AI・人工知能/LLMの使用に関する各ディストリビューションのポリシーの違いという問題も潜在的な障害になりつつありますし。

従って、フィルタリングを回避したり、独自のフィルタリングリストと差し替えて辞書データを作成できるようにしたり、そのようなノウハウ自体のドキュメント化をしておくことは、今後各ディストリビューションの公式／非公式パッケージとして配布する上では避けて通れない道だと考えています。

又、Mozcも3.x系になって、外部辞書の追加がより容易になったようです(これから試験していきますが)。その辺りのノウハウ文書も追々入れていこうと思います。

## Download

```
git clone --depth 1 https://github.com/utuhiro78/merge-ut-dictionaries.git
```

## Configure

Comment out unnecessary dictionaries in `src/merge/make.sh`.

Default settings:

```
#alt_cannadic="true"
#edict2="true"
jawiki="true"
#neologd="true"
personal_names="true"
place_names="true"
#skk_jisyo="true"
sudachidict="true"
```

## Build

```
cd src/merge/
sh make.sh
cat mozcdic-ut.txt >> ../../../mozc-master/src/data/dictionary_oss/dictionary00.txt
```

Build Mozc as usual.

## Option: Generate the UT dictionaries using the latest stuff

Uncomment ```#generate_latest="true"``` in `src/merge/make.sh`.

It downloads the latest "jawiki-latest-pages-articles-multistream.xml.bz2" (over 4.2 GB).
